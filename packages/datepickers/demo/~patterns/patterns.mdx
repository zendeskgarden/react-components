# Patterns

## Render calendar in a root level React portal

The `appendToNode` property can be used to render the calendar in a different
DOM location than inline with the DatePicker component. This is done via React
portals under the hood.

You typically will need to set this property if you are using the `DatePicker`
inside an element with `overflow: hidden` / `auto` / `scroll` CSS styles.

See in this example, that the calendar is currently getting cropped. Enable the
`appendToNode` property to see the full calendar.

## Custom date format

`formatDate` and `customParseDate` let you display and parse dates in a
format other than the default. They work as a matched pair: `formatDate`
controls how the committed value is displayed in the input, and
`customParseDate` controls how typed text is read back into a `Date`. Both
need to agree on the same shape, otherwise typed input stops parsing
correctly once the field reformats to the committed value.

## Surfacing an invalid date

`onValueSettled` reports `{ date, inputValue, valid }` whenever the field's value settles — on
blur after typing, or when a date is selected from the calendar. Unlike `onChange`, which only
fires for dates that parse successfully, `onValueSettled` fires either way, so it's the signal to
use for driving a `Field.Message`/`Input` `validation` state. Because it only fires on
blur/selection rather than on every keystroke, an error won't clear until the field settles again
— it's meant for validating a completed entry, not live-as-you-type feedback.

Typing text that can't be parsed into a date (e.g. missing the year) reports `valid: false`:

## Surfacing a date outside the allowed range

`onValueSettled` also reports `valid: false` for a date that parses correctly but falls outside
`minValue`/`maxValue` — the same range a disabled calendar day already enforces, now enforced
for typed input too:

## Surfacing a required field left empty

`onValueSettled` treats an empty field as valid by default, since "nothing entered yet" isn't
the same as "entered something wrong." It only reports `valid: false` for an empty field when
the input element passed as `DatePicker`'s child has the native HTML `required` attribute:
